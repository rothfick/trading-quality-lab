# Trading Quality Lab

Risk-driven quality engineering against a pinned [OpenAlgo](https://github.com/marketcalls/openalgo) revision. This is an independent learning and portfolio project, not an official OpenAlgo test suite.

**Current milestone: iteration 01 — foundations.** One parameterized component test exercises the real order schema with five quantity examples. A controlled mutation demonstrates that the zero-quantity assertion detects a weakened boundary. No trading application, broker, database or AI model is started.

## Quick start

Prerequisites: Git and [uv](https://docs.astral.sh/uv/getting-started/installation/), with access to GitHub and the Python package index during setup. uv manages Python 3.12. Run from the repository root:

```bash
uv sync --locked
uv run --locked python -m harness.lab bootstrap
uv run --locked python -m harness.lab doctor
uv run --locked python -m harness.lab test
uv run --locked python -m harness.lab prove
```

`bootstrap` fetches exactly the commit in [upstream.json](upstream.json). An existing matching checkout is reused; a mismatched checkout is rejected without resetting local work. Python dependencies are separate from the application's environment. Once dependencies and source are cached, `uv run --offline --locked python -m harness.lab prove` needs no broker, model or market connection.

`test` must be green. During `prove`, a second pytest run deliberately prints **one failure** for `zero-rejected`; the overall command succeeds only when that exact assertion kills the mutant. Any other failure, setup error, skip, missing report or zero-test run fails the command. This is a focused sensitivity check, not a mutation coverage score.

Generated JSON provenance and JUnit reports are in `quality-lab/reports/generated/` (ignored by Git, uploaded by CI). `baseline.xml` should have 5 passes; `mutant.xml` should have 4 passes and 1 assertion failure. `mutation-proof.json` records `status: killed`. A later run replaces these files.

## What this proves

For the pinned schema, a synthetic NSE LIMIT order rejects quantities -1, 0 and 0.5 and accepts 1 and 2 as integers. Expectations are literal examples, not values generated by the same implementation. The real `OrderSchema` module and its real constants are loaded, without executing the API package initializer. See [ADR-002](quality-lab/docs/adr/002-schema-component-boundary.md).

This does **not** prove API authorization, absence of side effects after invalid requests, persistence, broker execution, price validity for an instrument, funds, P&L or a complete order lifecycle. Characterizing current behavior is not approving every business rule.

## Local checks

```bash
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked python -m harness.lab prove
```

GitHub Actions runs the same checks on Ubuntu, with read-only repository permissions and pinned action revisions. Workflow existence is not evidence of an executed hosted run. Branch protection must be configured separately after the first successful GitHub run.
